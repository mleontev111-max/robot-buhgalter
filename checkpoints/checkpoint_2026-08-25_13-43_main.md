### ✅ Проверенные проблемы аудита
1. **CI красный на серии коммитов main.** Основной источник — `eslint .`: shadcn/ui генерирует ложноположительные ошибки строгих React rules, плюс есть реальные ошибки в `src/lib/importer.ts`.
2. **Данные приложения живут в localStorage.** Это неприемлемо как постоянное хранилище бухгалтерии и SaaS.
3. **API credentials хранятся в localStorage в открытом виде.** Их нельзя считать безопасными для production.
4. **Нет unit-тестов налогового движка.** `tax.ts` и `organizationTax.ts` критичны для корректности расчётов.
5. **`server.pid` закоммичен в репозиторий.** Нужно удалить и добавить `*.pid` в `.gitignore`.
6. **CORS sync-сервера слишком широк:** `cors({ origin: true })`.
7. **Публичный GitHub Pages фронтенд зависит от локального `http://localhost:8787`.** Это dev-only архитектура, не production.
8. **`Home.tsx` содержит устаревшую загрузку `wb-sync.json`.** Источник больше не является частью основной архитектуры и должен быть удалён/заменён.
9. **`useAppState()` возвращает новый объект на каждый рендер.** Это осложняет корректные зависимости эффектов.
10. **Налоговые константы захардкожены как `TAX_2026`.** Перед 2027 нужно перейти на таблицу налоговых правил по годам.
11. **Нет Prettier-конфига, часть файлов плохо читаема.** Форматирование надо стабилизировать после восстановления CI.

## 🧠 Архитектурные решения, которые сохраняем
- Один налогоплательщик может иметь несколько режимов и торговых направлений.
- Два Ozon кабинета ИП Леонтьева — два `SalesChannel`, но одна база УСН 6% этого ИП.
- Банк не заменяет финансовый отчёт маркетплейса при определении налоговой выручки.
- Для розницы ПСН основным источником фискальной выручки будет ОФД/касса; эквайринг используется для сверки.
- Неполные данные не должны отображаться как окончательный налог.
- Платёж из календаря не равен подтверждённой задолженности ФНС без сверки с ЕНС.
