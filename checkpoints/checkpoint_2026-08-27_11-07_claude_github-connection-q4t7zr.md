## 🧠 Контекст и архитектурные решения

- Реестр `TAX_RULES_BY_YEAR` — это **инфраструктура**, не данные на будущее.
  Когда появятся официальные параметры 2027 года — добавить запись в реестр,
  весь остальной код подхватит её без изменений сигнатур.
- `TAX_2026`/`calcInsurance2026` оставлены публичными экспортами специально —
  как алиас 2026-года для кода, который явно хочет на нём зафиксироваться.
- Шифрование ключей — **опциональное**, не форсируется на существующих
  пользователей. Пароль теряется — теряются и ключи безвозвратно (по дизайну,
  как у любого AES-GCM-хранилища); единственный откат — удалить подключение и
  ввести ключ заново.
- Ветки `feature/tax-2026` / `architecture/multi-tenant-domain-model` на
  GitHub — не чья-то параллельная работа, а мусор от уже смёрженных 19.08
  PR #1/#2. GitHub не удаляет ветки автоматически после мёржа.
- Работа над проектом ведётся минимум двумя независимыми сессиями/агентами
  (эта + «GPT-5.6 Sol»), чекпоинты — общий канал синхронизации между ними.
  Перед началом любой сессии — сверяться с `git log`, `checkpoints/*.md` и
  открытыми ветками/PR на GitHub, а не только с локальным контекстом.
