## 🗺️ Где мы находимся

### ✅ Что уже сделано
1. Многопользовательская доменная модель: User → Organization → TaxRegistration → BusinessUnit → SalesChannel.
2. Два ИП, совмещение ПСН + УСН 6%, налоговое ядро 2026, реальные параметры патентов.
3. Страховые взносы считаются на уровне ИП, а не дублируются по магазинам.
4. Проверка полноты данных, налоговый календарь, журнал фактических налоговых платежей.
5. Экспорт данных для бухгалтерской проверки без API-ключей.
6. Поддерживаются несколько кабинетов одного маркетплейса. У ИП Леонтьева Ozon №1 и Ozon №2 — независимые channelId/credentials внутри одного УСН 6%.
7. Повторная синхронизация одного внешнего кабинета заменяет только операции его `channelId` и не трогает второй кабинет того же маркетплейса.
8. Добавлена матрица финансовых отчётов по Ozon/WB/Яндекс/Авито.
9. Сервер синхронизации теперь возвращает метаданные покрытия: период, число операций, режим источника и признак полноты.
10. Интерфейс показывает, является ли синхронизация финансовой или предварительной.

### 🔄 В работе
1. **Финансовые адаптеры маркетплейсов**
   - Ozon: уже используется финансовый API операций; два Client-Id поддерживаются раздельно.
   - WB: финансовый отчёт используется, но адаптер нужно сверить/обновить под актуальную версию Finance API и убрать зависимость от устаревающих методов.
   - Яндекс: пока синхронизация строится на API заказов и маркируется как предварительная. Следующий шаг — генерация/получение финансовых отчетов `goods-realization`, `united-returns`, `united-marketplace-services`, `united-netting`.
   - Авито: API заказов остаётся ограниченным источником; нужен fallback на файловую финансовую выгрузку + банковскую сверку.

2. **Банки и розница**
   - Точка: банковская выписка.
   - Альфа: эквайринг.
   - ОФД/касса: основной источник розничной выручки ПСН.

## 🧠 Архитектурные решения
- Налог считается на уровне Organization.
- ПСН и УСН — разные TaxRegistration.
- Каждый внешний кабинет — отдельный `channelId`.
- Ozon №1 и Ozon №2 складываются в одну базу УСН только на уровне ИП.
- Банковская выплата маркетплейса не является заменой налоговой выручки из отчёта площадки.
- Неполный источник не должен выглядеть как окончательный налоговый расчёт.
- API-ключи не попадают в GitHub и в бухгалтерский экспорт.
